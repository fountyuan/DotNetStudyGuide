各模块职责说明
模块	职责	核心实体
Inventory	库存管理	Warehouse, Location, Product, Stock, InventoryTransaction
Order	订单管理	Order, OrderItem, Shipment, OrderStatus
Purchase	采购管理	PurchaseOrder, PurchaseOrderItem, Supplier
Sales	销售管理	SalesOrder, SalesOrderItem, Customer
Report	报表分析	InventoryReport, OrderReport, PerformanceReport
数据库设计（多数据库/单数据库）
方案一：分库（微服务架构）
text
WMS_Inventory_DB    # 库存数据库
WMS_Order_DB        # 订单数据库
WMS_Purchase_DB     # 采购数据库
WMS_Sales_DB        # 销售数据库
WMS_Report_DB       # 报表数据库（只读副本）
方案二：单库（单体架构）
text
WMS_DB
├── Inventory_*      # 库存表
├── Order_*          # 订单表
├── Purchase_*       # 采购表
├── Sales_*          # 销售表
└── Report_*         # 报表表

这种结构适合 WMS 系统的特点：

✅ 模块化：每个业务模块独立

✅ 可扩展：可以按模块独立部署和扩展

✅ 可维护：代码职责清晰

✅ 可测试：模块独立测试

✅ 可复用：框架层和构建块被所有模块共享

技术栈建议
层	技术选型	说明
Web 管理后台	React + TypeScript + Ant Design	企业级后台
桌面应用	.NET 8 + WPF/MAUI	Windows 桌面
移动 PDA	React Native + TypeScript	跨平台
报表系统	RDLC + FastReport	专业报表
API 网关	ASP.NET Core + Ocelot/YARP	统一入口
实时通信	SignalR + WebSocket	实时推送
打印服务	Zebra 打印 + 标签设计	物流标签
这样的界面层设计能满足 WMS 系统的所有用户场景，从管理层到操作层都有合适的界面！
